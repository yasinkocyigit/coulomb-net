# Coulomb-Net: Deep Learning for Inverse Electrostatic Problems

## 1. Abstract and Project Purpose

Coulomb-Net is a specialized, deep learning-based computational framework developed using PyTorch. Its primary objective is to solve a highly complex, non-linear inverse problem in the domain of classical electromagnetism: predicting the fundamental, unobservable scalar properties of interacting bodies (specifically, their electrostatic charges $q_1$ and $q_2$) based solely on observable macroscopic phenomena and spatial geometries.

In traditional computational physics and molecular dynamics, simulators rely on a "forward problem" methodology. If the physical properties (charge, mass) and the spatial coordinates of particles in a system are known, one can easily compute the resulting forces and fields using deterministic mathematical equations (such as Coulomb's Law). 

However, this project reverses that paradigm to tackle the **Inverse Electrostatic Problem**. In many real-world experimental setups, sensor networks, or complex material science observations, the exact charge distributions of individual particles are unknown. Instead, scientists can only measure the resulting macroscopic effects: the total Electric Field magnitude ($|\vec{E}|$) at certain points, the total electrostatic Force magnitude ($|\vec{F}|$), and the spatial coordinates ($x, y, z$) of the bodies. 

Coulomb-Net acts as an intelligent surrogate model. By feeding the neural network a 15-dimensional input vector consisting of purely observational data—particle coordinates, Euclidean distances between them, and the net field/force magnitudes—the Multi-Layer Perceptron (MLP) learns to untangle the overlapping physical interactions and accurately predict the original source charges ($q_1$ and $q_2$).

### 1.1 Core Applications and Real-World Significance

The implications of successfully modeling this inverse relationship are substantial:
* **Sensor Data Inversion:** In experimental physics, when sensors detect localized electric fields or forces but the source is obscured or moving, Coulomb-Net provides a methodology to deduce the source properties directly from the sensor data.
* **Physics-Informed Machine Learning:** This project bridges the gap between pure data-driven machine learning and physical laws. It demonstrates how neural networks can map strict inverse-square physical laws without explicitly being programmed with the formulas.

## 2. Theoretical Background and The Physics Engine

To understand the complexity of the task Coulomb-Net performs, one must look at the underlying physics governing the dataset.

### 2.1 The Forward Mathematical Model
In a closed system containing charged point particles, the interactions are governed by Coulomb's Law. The electrostatic force vector $\vec{F}_{12}$ exerted by charge $q_1$ on charge $q_2$ separated by distance $r$ is calculated as:

$$ \vec{F}_{12} = k_e \frac{q_1 q_2}{r^2} \hat{r}_{12} $$

Similarly, the Electric Field $\vec{E}$ generated by a point charge at a specific distance is:

$$ \vec{E} = k_e \frac{q}{r^2} \hat{r} $$

When multiple particles interact in a 3D coordinate space ($x, y, z$), these forces and fields obey the principle of superposition. They add together as vectors.

### 2.2 The Complexity of the Inverse Problem
While calculating the above formulas is trivial for a computer, Coulomb-Net attempts to do the reverse: $F_{total}, E_{total}, r \rightarrow q_1, q_2$. 

This is mathematically ill-posed and extremely difficult for traditional linear regression for three reasons:
1. **Information Loss via Magnitudes:** The network is only given the scalar magnitudes of the Force and Electric Field, not their vectors. This means directional information is lost, creating mathematical ambiguities.
2. **Non-Linearity:** The inverse-square nature of the distance ($1/r^2$) means that tiny changes in spatial position cause massive spikes in force (singularities), making the data distribution highly skewed.
3. **Superposition Entanglement:** The total field is a blended sum of multiple charges. The network must learn to mathematically "un-blend" this field to isolate $q_1$ from $q_2$.

Coulomb-Net successfully overcomes these hurdles through deep representation learning, utilizing adaptive oversampling for physical edge-cases and a carefully tuned MLP architecture.

## 3. Project Features and Technical Highlights

* **Physics-Aware Synthetic Dataset Generation (`ThreeChargeDataset`):** The project does not rely on static external CSV files. It features a built-in, highly optimized physical engine that procedurally generates millions of controlled 3-particle interactions. It calculates precise Euclidean distances, exact vector math for forces, and utilizes adaptive oversampling to ensure the neural network learns from rare physical anomalies (like particles spawning extremely close to each other).
* **Deep Neural Network Architecture (`ChargePredictorNet`):** A customizable Multi-Layer Perceptron designed specifically for continuous multi-target regression. It utilizes specialized activation functions, dropout layers for regularization, and a multi-dimensional hidden space to capture the non-linear physics.
* **Comprehensive Academic Diagnostic Suite (`extra_viz.py`):** The repository goes far beyond simple loss curves. It produces academic-grade statistical and diagnostic visualizations, including Parity Plots, Residual Q-Q plots, Scale-Location plots, and Feature Correlation Heatmaps to rigorously evaluate the model's adherence to the physical laws.
* **Decision Tree Baseline Benchmarking (`baseline_tune.py`):** To prove the efficacy of the Deep Learning approach, the framework integrates parallel training with `scikit-learn` to build Decision Tree models. This establishes strong mathematical baselines and extracts interpretable Feature Importance metrics to see which physical traits (distance vs. field) the algorithms rely on most.

## 6. Configuration Management

All core hyperparameters and physics simulation boundaries are managed via `config.yaml`. This ensures experiments are perfectly reproducible without modifying source code.

**Key Parameters Include:**
- `samples`: Total number of synthetic physical interactions to simulate.
- `position_range`: The 3D spatial boundary ($[-x, x]$) where particles are allowed to spawn.
- `charge_range`: The mathematical limits for the electrostatic charge values to be predicted.
- `hidden_dims`: Architecture of the Multi-Layer Perceptron (e.g., `[512, 256, 128]`).
- `lr`, `batch_size`, `epochs`: Standard deep learning training hyperparameters.
- `patience`: Early stopping threshold to prevent the model from overfitting on the physical data.

## 7. Usage and Execution

The entire experimental pipeline is executed through the `main.py` entry point using command-line arguments.

**1. Standard Physical Training Run:**
```bash
python main.py --config config.yaml
```
*Generates the physical dataset based on the YAML limits, trains the neural network, evaluates it on the test set, and saves standard regression metrics and loss curves.*

**2. Deep Diagnostics and Scientific Visualization:**
```bash
python main.py --config config.yaml --extra_viz
```
*Triggers the extended visualization suite in `extra_viz.py` to generate rigorous scientific plots (Parity plots, Residual distributions, Scale-location plots) to deeply analyze the model's predictive accuracy and physical validity.*

**3. Baseline Comparisons and Full Academic Run:**
```bash
python main.py --config config.yaml --extra_viz --with_tree --early_stopping
```
*Executes the full suite: applies early stopping, trains a parallel Decision Tree baseline, and compares the physical feature importances learned by both algorithms.*

## 8. Outputs and Analytics

To maintain clean experimental tracking, a timestamped directory is automatically created inside `outputs/` upon every execution. This output includes:

1. **Regression Metrics (`metrics_...txt`)**: Comprehensive logging of Mean Squared Error (MSE) and R-squared ($R^2$) scores for the predicted charges $q_1$ and $q_2$.
2. **Core Visualizations**: 
   - `loss.png`: Training vs Validation loss curves over epochs.
   - `predictions.png`: True vs Predicted charge values scatter plot.
   - `residuals.png`: Error distribution analysis across the physical spectrum.
3. **Advanced Diagnostics** *(If `--extra_viz` is used)*: Correlation heatmaps of the 15-dimensional input space, feature scatter matrices, and Q-Q plots for error normality checks.

*Note: Due to version control file size limitations, trained PyTorch model weights and heavily populated generated physical datasets (such as `outputs/`, `exp/`) are excluded from this repository via `.gitignore`. The model dynamically regenerates the required physical environment upon running `main.py`.*
